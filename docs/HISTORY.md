## Roadmap ทั้งหมด (จาก outline 5 ระบบของผู้ใช้)

- **เฟส 1 (เสร็จ):** loot/อุปกรณ์ · หลบ+telegraph+hit-stop · เอลีท · แต้มคุณสมบัติ · waystones
- **เฟส 2:** ต้นไม้ทักษะ ✅ · ร้านค้า/ช่างตีเหล็ก/วัสดุ ✅ · มินิบอส+ประตูผนึก ✅ · **บอสเฟส 3 ⏳ (ถัดไป)**
- **เฟส 3 (ยังไม่เริ่ม):** อาชีพเลี้ยงสัตว์/summoner · พื้นที่ Act 2 (ทางเหนือหลังซากวิหาร) · กลางวัน-กลางคืน มอนกลางคืนแรงขึ้น ·
  เสียง (Web Audio) · เควสต์สุ่มหลังจบเนื้อเรื่อง · (ระยะยาว) co-op ผ่าน WebSocket

## บทเรียน / กับดักที่เจอแล้ว

- `$('hud-player')` เป็น null ทำ HUD พังเฟรมแรก — เจอด้วย smoke harness ไม่ใช่ตาเปล่า → ทุกระบบใหม่ต้องมี assertion ใน smoke
- Headless Chrome (SwiftShader) เรนเดอร์โหมดเกมเกิน 10 นาที → เลิกใช้ ใช้ Node harness (fake DOM + stub renderer) เท่านั้น
- smoke ไม่นิ่งเพราะเทสต์เอง (spawn สุ่ม, `auto=1` ยิงสกิลระหว่างเช็ค, ตีบอสจากไกลแล้วบอส return/leash-heal,
  ไอเทมดรอปในรัศมีเก็บอัตโนมัติ, นับ summon แบบ `=== +2` ชนกับเอลีทธรรมชาติ) — teleport/ปิด auto/นับแบบ `>=` ก่อนแตะโค้ดเกม
- อัปเกรด +8% บนสถิติจำนวนเต็มเล็ก ๆ ปัดแล้วไม่เพิ่ม → `Items.lines` การันตี ≥ +1 ต่อขั้น
- คำสั่ง chain ที่ commit/push ต้องต่อด้วย `&&` หลัง smoke เสมอ (เคยหลุด commit ตอนเทสต์แดง)

## เริ่มงานบนเครื่องใหม่

```
git clone https://github.com/worawutinsiri/thornwild.git
cd thornwild
node tools/smoke.mjs        # ต้องขึ้น "smoke ok" (ครั้งแรกโหลด three.min.js ไว้ .cache/)
start index.html            # เล่น (ต้องต่อเน็ตเพื่อโหลด Three.js/ฟอนต์)
```

ถ้าจะให้เครื่องนั้นรับคำว่า "deploy" แบบเดียวกัน ให้สร้าง IIS site ชี้ที่ `C:\inetpub\thornwild` แล้วใช้ `tools/deploy.ps1`
(หรือส่ง `-Dest <โฟลเดอร์อื่น>`)
